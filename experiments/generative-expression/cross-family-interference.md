# R5：条件与无家族条件生成的家族连贯性诊断

状态：2026-11-17，本轮决定不补充执行。本文作为未委托执行的预案留档，尚无执行器、校准或新生成结果，也不修改论文。若将来重新决定开展，仍须先冻结家族、片段、读出和随机种子清单。

不补跑的理由是证据增量有限：当前主结论不依赖“参数记忆竞争”这一机制，而本小实验只能诊断与其一致的生成表型，不能独立识别该机制。R5 继续将跨家族干扰列为可检验解释，不列为已验证结果。

## 核心问题

模型生成不同家族的序列，本来就是正常的混合分布。真正值得检查的是：**同一段新生成序列能否维持一个连贯的家族状态，还是出现超出参考分布的跨家族混杂；提供更多目标序列前缀后，这种现象是否仍存在？**

本实验只改变目标序列自身的前缀，不提供额外同源或竞争序列，不修改权重。外部同源上下文生成 E11 属于 [R4](../context-access/README.md)，不在这里重做。这里的“条件”是原生氨基酸前缀，不是给不支持家族标签的模型添加标签，也不是把条件化模型的标签删掉。

阳性最多支持“与跨家族记忆干扰一致的生成表型”。一般续写失稳、家族路由不足等仍是替代解释；没有干预训练中的家族暴露，就不能证明参数内部的竞争存储。跨家族组合也可能有用，不能据此认定其不能折叠或没有功能。

## 固定一个模型和一个生成接口

使用已部署的 **ProGen2-medium**。它具有原生单残基表示和已有的 AA20 定长采样路径，避免为 LLaMA 的合并词元另做复杂的残基长度控制。本轮不加入第二个模型，不微调、不做 RL、不折叠。

所有条件使用同一检查点、bfloat16、同一原生 n-to-c 起始标记及同一采样规则：temperature 1、top-k 关闭、top-p 1、repetition penalty 1，仅允许 AA20，在达到总长前屏蔽结束标记。沿用已验证的 `use_cache=false` 路径；batch 8 仅在预试验通过既有输入／概率接口检查后采用，否则停止并重新评估预算，不偷偷改变接口。检查不要求不同批大小下的随机样本逐字相同。

这是**总长固定为 192 AA 的受控片段生成实验**，不是原生自由长度产率实验。“无条件”在本文中专指无家族条件，仍有共同的字母表和长度约束。不要将其与旧的自由长度、不同温度或不同提示协议的生成池直接合并。

| 条件 | 输入 | 新生成的残基数 | 用途 |
| --- | --- | ---: | --- |
| U | 仅原生起始标记 | 192 | 无家族条件的参照池，不指定“正确家族” |
| P16 | 起始标记 + 天然片段前 16 AA | 176 | 弱条件 |
| P32 | 同一片段前 32 AA | 160 | 中等条件 |
| P64 | 同一片段前 64 AA | 128 | 唯一主比较的强条件 |

只给 **65–128 位和 129–192 位**两个不重叠的 64-AA 窗口计分。它们在所有条件下均由模型生成；给定前缀不会直接贡献命中。不同前缀长度使用同一片段和配对随机流，不能以不同目标替代前缀干预。

可复用的实现边界是 `src/capability/decoding/guided_decoding.py` 的 AA20／定长原生采样、现有 ProGen2 adapter 和 `src/capability/generation/family_oracle.py`。这些不是已经存在的新实验执行器；本轮不新增执行代码。

## 先检验读出是否有资格回答问题

候选来源是 `results/extensions/family_distribution_20261106/queue.json` 的 64 个 evaluation groups。只读盘点显示，27 组各有至少 8 个长度不短于 192 AA 的 held-out representatives。这仅证明长度和数量资格，不证明有足够的单域家族、共同对齐区间或可识别窗口。

正式集合固定为 **8 个独立家族组，每组 4 个来自不同近重复簇的天然前缀来源**；另留 4 个不重叠组作技术预试验。家族、窗口和片段只按天然输入的覆盖、近重复关系、训练侧参考及预先固定的排序选定，不读取新模型输出。不能挑选模型最容易混淆的家族，也不能根据结果替换家族。

资格和读出规则：

- 选择一个共同的 192-AA 单域区间；用于条件前缀和 Profile 对照的片段必须具有可核实的查询坐标对应关系，不能把插入／删除造成的错位当作家族混杂。
- Profile 仅使用既有 training-cluster representatives 和对应的冻结参数。若无法取得匹配的 Profile 或对齐区间，不另开搜索／Potts 拟合战役；记录资格不满足。
- 使用固定版本的 Pfam HMM 和现有 `--cut_ga` 规则。`any_family` 允许部分域命中，但不能假定 64 AA 足以识别。不得将完整域的 80% coverage 门槛误用于这些短窗口。
- 在训练侧天然片段上固定 family/clan 消歧映射与窗口规则，再冻结候选清单，用未参与选择的天然片段检查读出。重叠命中、同 clan 内难以区分的命中和天然多域情况必须预先归为相同家族组或歧义，不能看过模型结果后选择最有利的标签。映射未知时不强行判为跨家族。
- 技术门：各正式家族的天然片段双窗可识别率至少 80%；天然片段合并后的假切换率不超过 5%；已知跨家族拼接正控的检出率至少 80%。这些是有限校准样本上的操作门槛，不是对总体灵敏度／假阳性率的置信保证。
- 拼接正控只用于证明检测器确实能检出窗口身份变化，不把拼接序列称为无功能蛋白。若冻结的 held-out 验证失败，停止，不换一批片段把读出“调到通过”。

若凑不齐 8 个合格独立家族，或者短窗口读出不合格，本实验不进入确认性生成。缺失命中不是干扰，也不是没有干扰。

## 对照与端点

天然对照使用同一家族、同一窗口定义的 held-out 天然片段。统计对照使用匹配的独立位点 Profile 样本。构造无家族条件的统计混合时，必须**先选一次家族，再从该家族产生整段序列**；不能逐位置切换家族分布，否则对照本身就制造了待检验的混杂。

两个新生窗口各自只接受预先声明的、无歧义的家族组标签。条件生成分为四类，全部尝试保留在分母中：

1. 两窗均属目标 A：目标家族连贯。
2. 两窗同属另一个家族：家族路由／条件不足，**不算内部混杂**。
3. 两窗可靠指向不同家族组：可识别的跨家族混杂。
4. 任一窗无法识别或有歧义：未知，不算连贯，也不直接算干扰。

另外单列长复制和重复。新生窗口与给定前缀共享至少 20 个连续残基的情况，作为显式前缀复制报告；模型和对照采用同一规则，复制尝试仍保留在总分母中，但不进入主混杂事件的分子。U 没有给定 AA 前缀，该项是“不适用”，不是零复制；P16 也没有足够长的给定片段触发这条规则，不能跨前缀长度比较它来推断复制机制。预训练复制无法由此排除。

**唯一主端点**是在 P64 下，模型相对匹配天然对照的双窗可靠异家族率增量：

\[
\Delta_f=m_{\mathrm{P64},f}-m_{\mathrm{natural},f},\qquad
\bar\Delta=\frac{1}{8}\sum_{f=1}^{8}\Delta_f.
\]

其中混杂率是上述第 3 类、且非显式前缀复制的尝试数除以全部尝试数，不是对未知样本赋予一个“质量为零”的分数。前缀剂量、目标特异性、同属外家族的比例以及 Profile 比较均作预先声明的解释性读出，不再增加一批显著性主张。

Profile 若主要产生 no-hit，不能靠“低混杂率”赢得比较。只有在双窗可识别覆盖与模型可比时，才解释两者的混杂差异；否则保留完整类别分布并将该对照标为读出不足。条件输入能否指定目标家族，要看整张“输入家族→输出家族”表及前缀剂量，而不是挑选几个成功例子。

U 池始终不指定错误家族。报告同族、异族、未知、歧义及重复的完整分布；不能将它与均匀八家族混合池的总量直接相减。固定提供由**第一窗**归层的家族转移表，再看第二窗，不能用“两窗已经同族”来定义共同 support。对冻结八家族之外的命中单列；某一第一窗家族少于 16 条时仅列计数，不解释其转移率。所有 512 次的覆盖率和未知率都要报告；共同 support 不足就停留在描述，不追加采样。U 不承担独立的参数干扰因果结论。

## 统计判断和停止条件

先在每个前缀内汇总，再在家族内等权汇总；**8 个家族才是主推断单位**。随机流、前缀和样本数不是额外的训练谱系或独立家族。报告八个 \(\Delta_f\)、方向一致性，以及预先固定的 10,000 次家族级配对 bootstrap 95% 区间；这种区间条件于本次有限样本池，不覆盖重新训练或新的家族选择。

- 区间下界大于 0，且读出门通过：支持在该固定片段接口下存在超出天然基线的跨家族不连贯表型。只有前缀确实具有家族特异性时，才进一步讨论“干扰”解释。
- 若主要是两窗同属外家族：结论优先是路由／条件不足。
- 若主要是未知、读出不可靠或区间太宽：未识别／未解决，不作为模型没有干扰的证据。
- 若区间能排除 5 个百分点的额外混杂，只能排除本配置、这些家族上的该量级表型。全零或退化 bootstrap 的零宽区间不能承担这个结论；只能另报有适用条件的有限样本概率界，或保持未解决。

不因阴性结果增加模型、家族、采样轮数或改阈值。没有结构和功能实验，不将家族切换解释为生物学功能失败。证明训练参数内的竞争机制需要另行控制训练暴露，本轮不开展。

## 固定规模

| 部分 | 尝试数 |
| --- | ---: |
| 正式条件生成：8 家族 × 4 前缀来源 × 3 前缀长度 × 2 随机流 × 8 次 | 1,536 |
| U：2 随机流 × 256 次 | 512 |
| 技术预试验：4 个独立组 × 2 前缀来源 × P32/P64 × 8 次 | 128 |
| **GPU 生成总上限** | **2,176** |

最多新生成 354,304 个 AA token，不含固定输入和控制标记。Profile 对照固定每个正式家族 64 条，共 512 条；已知拼接正控最多 64 条；天然校准／验证池按冻结清单取每家族至多 16 个独立代表，均在 CPU 处理，不借重采样扩大生物学样本数。技术预试验检查字母表／长度、前缀边界、批处理接口和基本读出覆盖，不用混杂效果来决定是否改方案；技术失败即停。

## 所需时间：依据、估算与上限

已测参考是同一 ProGen2-medium 的旧 H200 单元：

- `results/R6/generation_replication_20260927/cells/replicate_1__progen2-medium__unconditioned/generation_replication.json`：800 次尝试，1,042.968 秒，峰值显存 1,904,528,384 bytes，约 1.77 GiB。
- 同目录 `run_manifest.json`：NVIDIA H200、bfloat16、batch 8、400-token cap、`use_cache=false`；旧采样温度为 0.85、top-p 0.95，不同于本设计。
- 同目录 `attempts.jsonl`：306,716 个实际 generated token，均值 383.395，得到约 294 token/s 的历史整单元平均值。

按尝试数粗缩放约 47 分钟；按新生成 token 粗缩放约 20 分钟。**两者都只是参照，不是新方案的实测值、上下界或置信区间。**前缀计算、无 cache 的序列长度成本、AA 约束、实现方式和采样设置都会改变耗时；1.77 GiB 也不是新任务显存保证。
